# Frozen evaluation annotations

- `policy-gold-600.jsonl`: 600 seeded question-answer instances, seed 42, balanced across ten categories. The policy suite receives these declared assertions directly to isolate reconciliation and retrieval. It uses a deterministic evidence reader and TF-IDF lexical vectors, not live-model extraction or dense vectors.
- `live-ai-gold-30.jsonl`: 30 developer-curated two-session conversations with two questions each (60 total), independently declared gold assertions, transition labels, preserved facts, stale values, and answer aliases. Actual extraction, dense embeddings, graph retrieval, and the same LLM reader are used in the live suite, with deterministic unresolved-conflict protection in hybrid.

Gold annotations are explicit in source and are not generated by the evaluated model. Both sets are internal development data, not an external blind or third-party annotated benchmark. Prompts and validation were refined during development. The live set lacks SAME transitions; policy and regression tests cover duplicates.

Regenerate with `python3 scripts/freeze_data.py`. Generators: `backend/evaluate.py` and `backend/benchmark_data.py`. Raw result files preserve errors and actual provider/model/cache metadata.
